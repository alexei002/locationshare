# Свой цвет + свой трек по тапу — дизайн

Дата: 2026-11-18 · Размер: маленькое изменение (два точечных изменения в MainScreen/Format/Repo/Prefs)

## Что и зачем

1. **Свой цвет.** Участник выбирает свой цвет (пин, чип, карточка, трек) — видят все в группе.
   Сейчас цвет назначается автоматически (`colorMapFor`: сортировка id → палитра из 16).
2. **Свой трек — по тапу, как у чужих.** Выбрал себя (пин/чип/строка в кластере) — видишь свой
   затухающий трек, как у остальных устройств.

## Найденная первопричина (воспроизведено на Redmi Note 11 Pro, сборка 2026.11.24)

- Тап по чипу «Вы» → трек рисуется (подтверждено пиксельным сравнением скринов: +~940 px цвета пина).
- Тап по строке в карточке кластера → только `focusId`/`focusTrigger` (камера), `selectedId` не
  ставится → трека и карточки нет.
- Свои пин часто схлопнут в кластер с другим устройством (дома два телефона рядом) — тапнуть
  свой пин нельзя. Итог: единственный рабочий путь (чип) неочевиден, «естественные» пути не работают.

## Решение

### 1. Выбор устройства из карточки группы (баг-фикс)

- Строка в `groupCard`: `selectedId = d.id; selectedGroup = null` + фокус камеры, как раньше.
- Пин выбранного устройства не прячется в кластере:
  `setVisible(d.id !in groupedIds || d.id == selectedId)` — иначе трек есть, а пина не видно.

### 2. Выбор своего цвета

- **UI**: Настройки, под полем имени — заголовок «Цвет на карте» и ряд из 16 кружков палитры
  (`FlowRow`, тот же набор, что в `Format.kt`) + вариант «Авто» (сброс). Выбранный — с обводкой.
- **Хранение**: `Prefs.customColor: String?` — `"#RRGGBB"` или null (= авто).
- **Публикация**: поле `color` в `devices/{id}/current`:
  - включается в payload `publishCurrent` (current перезаписывается целиком — без этого поле стиралось бы);
  - при смене цвета — немедленная запись `Repo.setColor()` (не ждать следующей точки).
- **Чтение**: `DeviceState.color: String?` → `parseColorHex()` в `Format.kt` (чистый Kotlin, без
  android.graphics — тестируемо).
- **Назначение**: `colorMapFor(ids, custom)` — устройства с кастомным цветом его фиксируют,
  остальные получают цвета палитры по порядку, **пропуская занятые кастомные** (уникальность
  сохраняется, пока палитры хватает).
- Точки использования `colorMapFor` (MainScreen + MapArea) переходят на новый вариант.

## Не-цели

- Произвольный цвет («пипетка»), альфа.
- Always-on свой трек, настройки видимости трека.
- Разрешение коллизий, когда два устройства выбрали один цвет (палитра общая — сознательный выбор).

## Проверка

- Юнит-тесты: `colorMapFor` с кастомными (приоритет, пропуск занятых), `parseColorHex` (валидное/мусор).
- На железе: кластер → строка «Папа (Вы)» → трек рисуется, пин видим; смена цвета в настройках →
  пин/чип перекрашиваются у всех участников.
